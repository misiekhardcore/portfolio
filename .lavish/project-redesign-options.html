The Decision

You want project pages to feel like rich articles with photos — narrative content with embedded media, not a data sheet. The core question is how much flexibility you need from the CMS editor and what the reading experience should feel like. Below are three approaches, from minimal change to full editorial control.

Option A

Rich Article + Photo Gallery

Minimal schema change

Keep the existing images[] and description fields. Render description as real rich text (headings, bold, lists, links) and add a photo gallery section that shows all images (not just the first). The details[] key-value pairs become a small sidebar or inline metadata section.

Suggested Path

Hybrid: Option A layout + Option C editor. Use the article-style layout from Option A (hero image, gallery grid + lightbox, details sidebar) but power the body content with the Lexical rich text editor with inline image upload from Option C. This gives you the best of both worlds: a polished, consistent page template with a dedicated photo gallery, plus the ability to drop images inline within the article prose for a natural editorial flow.

The only schema change is switching the rich text editor from Slate to Lexical with upload enabled. The existing images[] gallery field stays as-is for the photo grid. Option B (blocks) remains available if you later need per-project layout freedom, but the hybrid approach covers the core need with minimal disruption.
